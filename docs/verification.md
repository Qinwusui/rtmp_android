## 发现与修复

1. MI 8 虽报告 Surface 编码支持，但添加可选 profile / B-frame 参数时编码器拒绝配置（`0x80001001`）。使用必要的 Surface 格式参数后成功启动。该设备输出 High profile（100），解码能力需由接收端支持。
2. 渲染线程最初在每帧结束后额外等待 33ms，GPU 时间累加导致约 26fps。改用固定时间节拍后实测 30.01fps。
3. 唤醒手机触发 MIUI 人脸解锁，系统抢占摄像头（18:32:53 相机 0 断开，同时相机 5 开启）。加入相机恢复逻辑后，19:14:02 抢占、19:14:04 相机 0 恢复，音频、编码器与 RTMP 保持。
4. 最初的资源构造使用 `.also { start() }`，启动异常可能发生在赋值前。已改为先保存资源引用再启动，确保失败也完整关闭。
5. 曾尝试压缩 Release instrumentation；AndroidJUnitRunner 引用被主 APK 优化掉的共享 Trace / Kotlin facade，测试框架启动失败。未整体保留第三方包，改为 Debug instrumentation 与真实 Release 界面验证；不宣称 Release instrumentation 通过。
6. 修复活动界面销毁预览 Surface 时的 EGL 错误隔离，预览失败只移除预览，不终止编码管线。
7. 修复拥塞恢复关键帧错误重设同一连接时间戳原点的逻辑，加入区分清队列与重连的回归测试；旧传输回调在锁内校验连接代次，避免影响新连接。
8. 会话时长改用单调时钟计算，Android 17 局域网权限撤销纳入运行时检查；密码输入使用密码键盘并禁用自动更正。

## 2026-10-05 摄像头方向修复

MI 8 真机读取到 `SENSOR_ORIENTATION=90`，SurfaceTexture 的线性变换为 `[0,-1;-1,0]`，已包含传感器旋转。旧合成代码再次固定旋转 90°，且没有监听持握方向，造成重复旋转与横竖屏切换后侧转。

修复后保留生产者纹理变换，只追加设备持握方向对应的 GPU 旋转与居中裁剪。方向监听由采集管线持有，不依赖 Activity，设备平放/方向未知时保留最近有效方向，四个象限之间使用 5° 滞回减少抖动。编码器与输出分辨率保持不变。

- 新增方向单元测试 5 项全部通过，覆盖显示/物理方向换算、未知姿态、边界抖动、原生旋转不重复应用、四个方向的居中与比例。
- MI 8 真实 GLES / SurfaceTexture 测试使用四象限合成颜色，0°/90°/180°/270° 输出像素均符合预期；未导出真实摄像头画面。
- Debug、Release 构建和 app / capture Lint 通过。
- 修复版 Release 在 `nas` 配置上成功推流，约 29.8fps；用户实际持握切换并确认横竖屏均正常。
- 相机变换元数据探测与 GLES 测试的原始结果保存在本地 `artifacts/verification/`，不包含凭据和真实摄像头像素。
